# 콘텐츠 리서치와 편집 템플릿 운영

조사일: 2026-10-18 (Asia/Seoul). 목적은 실제 검색 출처와 공식 크리에이터 레퍼런스로 새로운 원고·촬영·편집 구조를 만드는 것이다. 조회수·구독자 수·실시간 순위는 이 문서의 선정 근거로 사용하지 않았다.

## 조사 범위와 증거

Google/Naver 공식 문서를 웹 검색으로 확인했다. YouTube 웹 텍스트 추출은 본문을 제공하지 않아, Aside의 `youtube` 스킬로 공식 업로더 검색 결과, 영상 메타데이터, 한국어 시간표시 자막을 조회했다. 공식 영상의 썸네일 이미지도 직접 확인했다. 아래의 **관찰**은 해당 영상 하나의 썸네일·메타데이터·자막에 한정된다. 영상 전체의 컷 길이나 화면 자막 노출 시간을 측정한 것은 아니다. **템플릿 제안**의 초 단위 길이는 우리 제품에서 실험할 제작값이며, 원본의 편집 수치 또는 성과 보장으로 취급하지 않는다.

`research` 스킬의 백그라운드 조사 역할을 이미 수행하는 Codex 서브에이전트가 이 문서를 작성했다. 중첩 위임 없이 한 파일에 근거를 모았다. 원본 영상·썸네일·전체 자막은 프로젝트에 복제하지 않았다.

## 편집 가능한 초기 템플릿 제안

아래는 전부 신규 구성이다. `title`, `text`, `duration`, `background`, `layout`, `assetUrl`, `trimStart`, `audioUrl`, `audioVolume`으로 현재 편집기에 저장할 수 있다. `narration`은 제작 원고이며 TTS 생성 기능이 아니다. 녹음·허가받은 음원은 별도 업로드한다.

| 템플릿 | 장면별 길이 | 구조와 편집값 | 검증할 가설 |
| --- | --- | --- | --- |
| 드라마 · 한 번의 선택 | 3 / 7 / 7 / 6 / 5초, 총 28초 | 훅 `center` → 상황 `lower-third` → 질문 `lower-third` → 반응 `lower-third` → 결말 `center`. 직접 촬영한 영상의 `trimStart`와 길이를 조정. 예시 배경 `#23382D`. | 얼굴을 가리지 않는 자막과 마지막 선택이 작은 화면에서도 이해되는가? |
| 재연 · 같은 순간 다른 선택 | 3 / 6 / 7 / 6 / 4초, 총 26초 | 재연 표시 `center` → 상황 `lower-third` → 어긋난 행동 `lower-third` → 결과 `split` → 사실/각색 구분 `center`. 예시 배경 `#4A302B`. | 실화로 오해하지 않으며 상황의 원인과 결과를 구별할 수 있는가? |
| 정보 · 질문 하나 검증 하나 | 3 / 4 / 8 / 7 / 5초, 총 27초 | 질문 `center` → 조건 `split` → 조작/근거 `lower-third` → 확인 결과 `split` → 출처·기준일 `center`. 직접 녹화한 화면 또는 자체 SVG를 업로드. 예시 배경 `#203849`. | 출처와 예외를 읽을 수 있고, 실제 조작 결과와 설명이 일치하는가? |

현재 편집기의 `split`은 영상 상단·텍스트 하단의 상하 분할 배치다. 서로 다른 영상 두 개를 동시에 재생하는 분할 화면으로 표시하지 않는다. 문장별 단어 애니메이션, 자동 화자 추적, 임의 좌표 콜아웃은 현재의 기본 템플릿 기능이라고 주장하지 않는다. 필요한 강조 원·화살표는 직접 만든 SVG/이미지에 포함하거나 후속 편집 기능으로 구분한다.

## 검색 소재 수집: 공식 출처와 한계

### Google Trends

- [한국 Trending now](https://trends.google.com/trending?geo=KR), [한국 RSS](https://trends.google.com/trending/rss?geo=KR), [Explore](https://trends.google.com/trends/explore?geo=KR).
- Trending now는 최근 검색 관심이 급증하고 뉴스와 연결되는 검색 묶음을 보여준다. 위치·기간·상태·정렬을 바꿀 수 있고 CSV·RSS 내보내기를 지원한다. 기본 정렬은 관련성이므로 수집 순서를 전체 검색량 순위라고 표시하지 않는다. 공식 안내는 평균 약 10분 갱신을 설명하지만, 우리 서비스의 실제 갱신 시각은 성공한 수집 시각을 기록해야 한다. [Google 공식 Trending now 안내](https://support.google.com/trends/answer/3076011?hl=en-uk)
- Explore 관심도는 표본을 시간·지역에 맞춰 정규화한 0–100 지표다. 절대 검색 횟수, 여론조사 결과, 해당 콘텐츠의 사실 여부가 아니다. 서로 다른 조건의 100을 같은 검색량으로 비교하지 않는다. 낮은 검색량의 0도 정확한 검색 0건을 뜻하지 않는다. [Google 데이터 FAQ](https://support.google.com/trends/answer/4365533?hl=en-GB)
- 도표·데이터를 콘텐츠에 사용할 때 Google Trends 출처를 표기한다. [공식 내보내기·인용 안내](https://support.google.com/trends/answer/4365538?hl=en)

### Naver DataLab

- [DataLab](https://datalab.naver.com/), [검색어 트렌드 화면](https://datalab.naver.com/keyword/trendSearch.naver), [공식 API 문서](https://developers.naver.com/docs/serviceapi/datalab/search/search.md).
- 검색어 트렌드 API는 입력한 주제어 묶음의 검색 추이를 일·주·월 단위로 반환한다. `ratio`는 결과의 최댓값을 100으로 놓은 상대값이다. 이 계약에는 네이버 전체의 실시간 인기검색어 순위를 돌려주는 필드가 없으므로, 이를 인기검색어 자동 순위 API로 취급하지 않는다.
- 현재 공식 문서 기준 최대 5개 주제어 묶음, 앱 등록과 Client ID/Secret, 하루 1,000회 호출 한도가 있다. ‘비로그인 API’는 최종 사용자 OAuth 없이 앱 자격증명으로 호출한다는 뜻이지 무인증이라는 뜻이 아니다. 자격증명은 서버에서만 사용한다. [Naver 공식 API 명세](https://developers.naver.com/docs/serviceapi/datalab/search/search.md), [공식 호출 한도 목록](https://developers.naver.com/products/intro/plan/plan.md)
- 현재 제품에서는 Naver 원문 URL과 키워드를 직접 기록한다. Google 수집 결과를 Naver 데이터처럼 합치거나, Signal 같은 별도 서비스의 목록을 네이버 공식 순위로 표시하지 않는다.

## 채널 → 소재 → 에피소드 운영 규칙

1. 수집 시 `keyword`, `source`, `url`, `capturedAt`을 보관한다. 원문이 실패하면 실패 상태를 남기고 이전 기록의 날짜를 현재로 바꾸지 않는다.
2. 채널의 대상 시청자와 포맷에 맞는 질문 하나를 선정한다. 트렌드는 소재 발견 신호로만 사용하고 사실의 근거는 정부·서비스 운영자·당사자 등 원출처로 다시 확인한다.
3. 레퍼런스에는 공식 URL, 관찰 위치, 실제 관찰한 점, 자체 제안을 분리해 적는다. 작품 속 인물·대사·사건·브랜드 디자인은 복제하지 않는다.
4. 에피소드 `notes`에 출처, 확인일, 사실/각색 구분, 촬영·음원 권리, 미확인 항목을 기록한다. 타인의 영상·스크립트·음악을 다운로드해 템플릿 재료로 사용하지 않는다. 직접 제작했거나 이용 허락을 확인한 자산만 업로드한다.
5. 초안 → 모바일 미리보기 → MP4 렌더 → 음성·자막·출처 확인 → 채널별 검수로 진행한다. 수정 전후 버전을 보존하고, 반복 사용할 구성만 템플릿으로 저장한다.

이 문서는 채널 관찰과 제작 제안이다. 선정 채널의 최신 성과·알고리즘 우대·우리 영상의 흥행을 입증하지 않으며, 원본 콘텐츠의 사실 주장도 별도 검증 없이 승계하지 않는다.
