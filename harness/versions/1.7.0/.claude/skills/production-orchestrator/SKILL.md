# Production orchestrator
## When to use this skill
Use for multi-stage episode work in FrameForge. Do not trigger for generic video recommendations, unrelated repositories or a simple spelling correction.
## Instructions
1. Run `node scripts/version-harness.mjs verify`, resolve `harness/manifest.json`, and read `docs/harness.md` plus role contracts inside its selected bundle. Load the live `.mex/ROUTER.md` and `llm-wiki/index.md` for current code and source context.
2. Resolve channel, episode, current version, goal and authorization. Create an absolute `_workspace/<run-id>/` manifest. For production execution, require a project-owned workflow ID/version and immutable template ID/version. Copy a reusable graph through `/api/workflows/:templateId/copies` with the expected template version and exact destination episode/channel. A fresh copy contains graph/config/lineage, not runs, jobs, sessions, credentials, paid intents, receipts or approvals. Project edits stay independent; shared-template changes create explicit new versions and never silently propagate.
3. Read the selected bundle's `.claude/agents/production-supervisor.md` and four specialist definitions. Reuse file-based roles; do not silently replace their contracts with unpromoted authoring changes.
4. Use the host's native subagents when available and explicitly authorized. Claude team mode requires its supported Agent Teams runtime; file presence is not runtime activation. Otherwise execute the same stages serially and record that mode.
5. Complete research, direction, editing and independent review in dependency order. Parallel research sources must have separate output paths.
   When using the graph, select the exact owned workflow/version and validate its DAG. Ten supported roles — trend, news, research, script, storyboard, layout, generate, render, review and publish — may repeat within 1–128 nodes/0–256 edges and the separate 1 MiB body limit. Unique node IDs bind inputs, outputs, history and retry. Actual edges determine deterministic topological order with lexical ID ties; same-role edges may be acyclic. Resolve connected prerequisites through intermediate roles, stopping each path at its nearest producer of the requested role. Missing/ambiguous required inputs reject; optional context may be absent, but ambiguous context rejects. Never select the first matching role.
   Partial runs use exact node IDs only in `selectedStages`/`startStage`; an explicit start requires all other selected nodes downstream. `resumeRunId` reuses branch-specific evidence only for the same terminal workflow/version and episode/version. Preserve per-node jobs and completed outputs after partial failure; uncertain identity blocks paid replay. Render combines relevant upstream generate outputs. Persist the run ID and observe every selected node. Hand each `awaiting_review` node its exact connected render candidate. The production DAG is separate from the knowledge graph, and a node does not automatically launch a specialist.
   For saved edits or narration, choose script agent `existing` so rerendering preserves authored scenes and audio. Use a generative agent only when replacing the storyboard is part of the requested change.
   A nonempty news `query` is exact and overrides title/topic, connected trend and supplemental keywords; only an empty/omitted query derives context. Requested Google News RSS errors or a response with no verified articles fail without sample/cached success. News-only selection preserves saved scenes and triggers no quote, generation, render or publication; bind evidence to exact node IDs. Retain publishers, article URLs/times and official guidance, distinguishing proposals from enactment. Subsequent authorized original cards/SAPI/local MP4 ending `awaiting_review` establish a source-only candidate, not acceptance, paid generation or public delivery.
6. Apply only validated, version-bound changes. Preserve inputs, failures and artifacts. Record unavailable integrations as unavailable.
   Restoring episode/workflow history creates a new version with a mandatory expectedVersion; never overwrite historical snapshots. Compare stable scene/node identities. Unsaved graph changes use bounded draft undo/redo.
   Higgsfield generation and slot layout are optional connected stages between storyboard and render, excluded from default graphs. Discover the selected transport's actual model schema only within authorized provider scope. Repeated scene-specific generate nodes each own a persistent job; prefer stable `sceneId`, while legacy `sceneIndex` remains accepted. `POST /api/workflows/:id/quote` must cover every selected node's exact input, scene/slot/assets/hashes/source type/rights/trims, per-node and combined costs (or explicit unquoted acknowledgement), expiry and human `{containsSyntheticMedia,rationale}` disclosure decision. Run only with matching plan ID/fingerprint/disclosure and explicit `allowGeneration:true`; changed inputs require fresh consent. Source-only editing makes no paid request. Developer API credentials, official MCP OAuth and host CLI accounts remain separate; project MCP retains lineage and never exports credentials.
   Persist the original node/scene request intent before submission, retain requestId and generation/provider job IDs, and reuse them after partial failure, cancellation, restart or resume. An uncertain or missing identity blocks replay. `POST /api/generations/:id/recover` polls existing provider IDs only. Verify actual local bytes/rights and approved input again before each paid effect. Apply at the exact expectedVersion without duplicate reapplication; stale edits retain output for explicit later apply. Cancellation may not stop an already submitted provider job.
   Import Commons originals through the source service's supported download path, with descriptive contact User-Agent, bounded download/probe/physical hash and separate explicit rights clearance. Current supported Commons originals are JPEG/PNG and WebM; do not infer permission or support from thumbnails, RSS/og:image or player URLs. Retain scene/slot source/rights/attribution/retrieval/hash/trim history. With no cleared footage/image, preserve the story in an original text-only title card with no invented image license or paid request. Render actual required credits legibly and include all scene/slot credits in the final server description. Generated/illustrative visuals are not factual event evidence. Missing provider configuration fails explicitly before fetching while local rights validation remains usable.
   Native narration uses installed Windows SAPI voices locally on Windows or through the authenticated host bridge from Linux Docker. Read `/api/speech/voices` and verify availability instead of assuming connectivity or a voice. Save the narration script, and submit `voice`, `expectedVersion` and optional `sceneIds`/`rate` to `/api/episodes/:id/narration`. The bridge accepts bounded text/voice/rate only and returns validated raw WAV bytes; never submit host paths. Wait for the persisted job result, reload its resulting episode version and inspect the attached audio before rendering. Missing credentials, unavailable voices, timeout or invalid audio remain explicit failures. Uploaded audio remains usable.
   After independent inspection and an owner decision or explicit review authority, record `approved` or `changes_requested` at `/api/workflows/:id/runs/:runId/review` with mandatory `reviewNodeId`, notes and exact rendered `expectedEpisodeVersion`. Preserve connected render/review IDs, review receipt, job ID, output URL and SHA-256. Decisions are per review node in `run.reviews[reviewNodeId]` and node outputs, with no new `run.review` alias; the run aggregates participating review outcomes. A conflict requires a new current candidate, not a substituted version number. Automated test decisions remain test evidence, not owner acceptance.
   Keep the selected project's node canvas as the sole default workbench. Open Studio/source/delivery/history/settings and other tools as native overlays from visible menus. Follow `docs/harness.md` for shared accessible context menus/tooltips and exact-target draft node/edge removal with incident cleanup, Undo/Redo and validated expected-version Save. Opening/navigation saves or executes nothing. Keep one live inspector/unique control IDs and resolve explicit stable sceneId/slotId exactly; unbound nodes retain project scene selection rather than guessing by role/order. Preserve full independent episode/graph stashes, selections, dirty/revision state and original saved base versions, including hidden unload protection. Ctrl/Command+S belongs only to the active scene or graph editor; stale explicit Save retains the draft and returns 409. `bindProject({episodeId,channelId})` is read-only and `getContext()` yields exact owned identities, null when unowned/ambiguous. Capture async target IDs/revisions before await; stale source/upload/tool reads and queued scroll/close/focus callbacks cannot switch project, overwrite stashes, redirect deleted-slot media, dismiss replacement overlays or steal focus. Mount/destroy permits sanitized local GET only; unknown origin/audience/disclosure remains unanswered.
   Project removal is confirmed recoverable archive, not deletion: authenticated same-origin admin `POST /api/episodes/:id/archive` and `/unarchive` accept only positive safe-integer expectedVersion. Open/cancel writes nothing; confirmed transitions append versions/history and retain project/graph/media/run/approval identities. Active production work and provider/browser/quote preflights block archive; archived edits/effects stay blocked until restore. Retained local history/media and cached browser inspection remain read-only; restore creates a new draft version without renewing authority.
   Keep technical review, generation consent and owner final publication approval distinct. A publish node currently creates local `publicationStages` with publication not attempted; it cannot complete the project. Prepare through `POST /api/publication/approvals` without provider traffic, show the complete exact fingerprinted server manifest/final description/credits, then use `POST /api/publication/approvals/:id/publish` only after the owner's `최종 승인하고 공개` for that displayed ID. Field/episode changes invalidate preview. State/list use `GET /api/publication/approvals/:id` and `GET /api/episodes/:id/publications`; recovery uses `POST /api/publication/intents/:id/resume`, without route aliases.
   Final approval binds owner/project/version/render hash, intended channel, rights/credits, metadata, explicit made-for-kids and synthetic-media decisions and disclosure rationale. Channel-bound OAuth requires a known external channel ID, verified granted force-ssl scope and exact authorized-channel match, with one-time state/PKCE/correlation-cookie/session protection. Upload privately, verify ID/channel/successful processing/metadata/audience/disclosure, revalidate the manifest, update that same video to public and read back again. Only verified public readback proves completion. Reconcile saved resumable/video identities after uncertainty without another insert; unknown stays unknown. Automated YouTube Studio attach/click/input/navigation is disabled; Studio is manual only. Keep tokens and opaque upload URLs in encrypted atomic 0600 private runtime files, never entities/events/history/state/knowledge/logs. Missing OAuth config and expiry/reconsent remain explicit prerequisites, not successful connection evidence.
7. For container migration, use the read-only SQLite snapshot utility into a new directory, then the verified snapshot importer into an empty dedicated volume. Preserve original data, partial failures and recovery routing; no destructive database/volume resets. Compare exact IDs, versions, history and media/review hashes, exercise the container adapters and verify persistence after restart before declaring cutover complete. A staging receipt is not proof that the production URL serves the container.
   File durable source/concept/report atoms with OKF frontmatter, update wiki index/log, refresh code graphs after code changes, and retain exact command evidence.
8. Report local render, QA, upload and publication separately with actual commands/counts/failures/prerequisites. Tests use explicit `loginToken:''`, `publicOrigin:''`, temporary DBs and ephemeral ports; fake only external transport and preserve independent test oracles. Passing fixtures grant no live provider, paid, consent, upload, deployment or Git authority. Authoring target 1.7.0 requires stable-source semantic gates followed by Main's new immutable promotion and integrity verification; preserve immutable 1.6.0 and earlier releases. Current focused runners are `node --test tests/node-workbench.test.mjs` and `node --test tests/project-archive.test.mjs tests/news-query.test.mjs`, not the former split-view smoke runner. Read the forthcoming sanitized `artifacts/node-native-workbench/verification.json` for actual stable-source results and prerequisites; the prior production-workspace-implementation receipt remains historical 1.6 evidence. Docker cutover requires separate actual-served-source/data-preservation evidence. Keep authoring changes working-tree-only until separately authorized Git publication. Stop only when the scoped result is verified or an exact blocking dependency remains.
## Examples
- Produce a 9:16 information episode from recorded Google trend evidence and an original editable layout.
- Revise a drama template, retain episode history and have an independent reviewer inspect the new candidate.
- Reconcile an episode version conflict before applying an agent-generated patch.
- Generate an installed Korean system voice, preserve the edited scenes with `existing`, and hand the resulting hash-bound candidate to review.
- Resume a terminal run to re-render and review without re-executing completed paid generation; verify the reused node outputs before approval.
## Best practices
Use original media or verified rights. Keep facts separate from fiction. Never copy credentials or private source footage into Git. A successful schema check does not establish factual truth or visual quality.
